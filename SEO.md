# Поиск: что сделано и что осталось сделать руками

## Чего добиваемся

Реалистичная цель — не «spotter». Это обычное английское слово, и по нему
в выдаче стоят приложения, споттинг-сообщества и сервис аналитики для
ютуберов; новый сайт туда не выйдет ни за какие деньги.

Достижимо и полезно:

* **споттер лайв**, **spotter грайм**, **спотер выпуски**, **русский грайм
  вживую** — это то, что набирают ваши зрители, и конкуренции там почти нет;
* **spotter live** — сложнее, домен `spotterlive.com` (испанский трекер
  самолётов) уже занимает выдачу, но за российскую выдачу бороться можно.

## Что уже сделано на сайте

До этого робот видел на сайте **231 символ**: меню, «Корзина», подвал. Весь
контент рисует js, а в исходном html блок `<main>` был пустой — индексировать
было нечего. Плюс все разделы жили после решётки (`#/episodes`), а всё, что
после решётки, поисковик за отдельную страницу не считает: в индексе могла
быть одна страница вместо тридцати.

Теперь при каждом деплое `build/prerender.py`:

* вписывает в `index.html` готовый текст — выпуски, составы с подписями,
  мерч, рассказ о проекте. Стало **7 500 символов** вместо 231;
* делает отдельные страницы со своими заголовками и `canonical`:
  `/episodes/`, `/merch/` и `/episode/<слаг>/` на каждый выпуск;
* собирает `robots.txt` и `sitemap.xml`;
* добавляет разметку Schema.org (Organization, WebSite, ItemList) — по ней
  поисковик понимает, что сайт и есть официальный SPOTTER.

Текст берётся из тех же `data/*.json`, что и сайт. Это не «отдельный контент
для робота»: через сотню миллисекунд js заменяет блок своей версией, и
посетитель видит обычный сайт. Правка из редактора → деплой → страницы
пересобираются сами, руками ничего делать не нужно.

## Что нужно сделать вам

### 1. Ссылки со своих площадок — самое важное

Для брендового запроса это весит больше всей технической части вместе
взятой: поисковик понимает, что сайт официальный, именно по ссылкам с ваших
же каналов.

* YouTube — раздел «Ссылки» в шапке канала;
* Telegram — описание канала и закреплённый пост;
* Instagram — шапка профиля;
* VK, если есть.

Везде — `https://spotterlive.ru`.

### 2. Яндекс.Вебмастер

<https://webmaster.yandex.ru> → «Добавить сайт» → `spotterlive.ru`.

Права подтверждены способом **«HTML-файл»**: файл `yandex_ae11e82afed140b2.html`
лежит в корне репозитория и уезжает в корень сайта обычным деплоем. Удалять
его нельзя — Яндекс перепроверяет права и снимает подтверждение, если файл
пропал.

(Способа «через Яндекс Метрику» в окне подтверждения не предлагается, хотя
счётчик на сайте стоит. Файл надёжнее в любом случае.)

Дальше:

* **Индексирование → Файлы Sitemap** → добавить `https://spotterlive.ru/sitemap.xml`;
* **Индексирование → Переобход страниц** → отправить главную;
* **Индексирование → Рендеринг страниц JavaScript** → включить
  «Рекомендую исполнять JS». Это бета и подстраховка: предрендер выше уже
  отдаёт роботу текст без всякого js, но с включённым рендерингом Яндекс
  увидит ещё и то, что дорисовывает скрипт;
* **Информация о сайте → Региональность** — поставить Россию;
* там же можно задать **официальное название сайта** — для брендового
  запроса это прямой сигнал.

### 3. Google Search Console

<https://search.google.com/search-console> → добавить ресурс `spotterlive.ru`.
Подтверждение проще всего через DNS-запись у регистратора домена.
Затем Sitemaps → добавить `sitemap.xml`.

### 4. Терпение

Первые заходы из поиска появятся через 1–3 недели после того, как сайт
попадёт в индекс. Проверять — в Метрике: **Отчёты → Источники → Поисковые
системы**.

## Что можно сделать дальше

* **Страницы участников** (`/artist/<имя>/`) статикой — 37 страниц под
  запросы вроде «JOLLO грайм». Сейчас они живут только после решётки.
* **Треклисты в выпусках** — сейчас на странице выпуска только состав.
  Названия треков это ровно те слова, которые люди ищут.
* **Полный переход на адреса без решётки** — чтобы и навигация внутри сайта
  шла по `/episodes/`, а не по `#/episodes`. Сейчас человек из поиска
  попадает на нужный раздел, но первый же клик по меню уводит на главную.
