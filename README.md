# SPOTTER LIVE — сайт

Статический сайт: чистые HTML, CSS и JS, без сборки и без сервера.
Значит, его можно положить на любой хостинг статики как есть.

---

## Что и куда заливать

**Заливать на хостинг:**

```
index.html
css/
js/
assets/
```

**НЕ заливать:**

```
.env          ← ключ YouTube API
tools/        ← локальные скрипты, серверу не нужны
README.md
.gitignore
```

> **Про `.env` — самое важное.**
> Если залить папку целиком, файл `.env` станет доступен по адресу
> `https://ваш-сайт/.env` — то есть ключ сможет скачать кто угодно.
> Заливайте только четыре пункта из списка выше.
> Если хостинг умеет только «всю папку» — удалите `.env` и `tools/`
> из того, что заливаете (локально они, конечно, остаются).

## Где хостить

Подойдёт любой статический хостинг. По удобству:

1. **Cloudflare Pages** — бесплатно, HTTPS сразу, быстрая раздача по всему миру.
   Можно перетащить папку мышкой в веб-интерфейс, можно подключить репозиторий.
2. **Timeweb / Beget / reg.ru** — обычный российский хостинг, если хочется
   оплату в рублях и поддержку на русском. Заливка по FTP.
3. **Yandex Object Storage + CDN** — если сайт живёт рядом с другими сервисами Яндекса.

Аудитория проекта на 70% русскоязычная, но и вариант 1, и вариант 2 отдают
статику быстро — принципиальной разницы для посетителя не будет.

**HTTPS нужен обязательно** — и не только ради замочка в адресной строке.
Без него не работают две вещи на сайте: кнопка «Скопировать заказ» и системное
меню «Поделиться» на телефоне. Браузеры разрешают их только на защищённых
соединениях. У всех вариантов выше HTTPS включается бесплатно.

## Что поправить перед первой заливкой

В `index.html` найдите строку с `og:image` и замените относительный путь
на полный, с вашим доменом:

```html
<meta property="og:image" content="https://ВАШ-ДОМЕН/assets/episodes/ch2-ep07-....jpg">
```

Это картинка, которая показывается, когда ссылку на сайт кидают в Telegram.
Часть сервисов не умеет разворачивать относительные пути, и превью выйдет пустым.

## Как обновлять потом

Все тексты, цены, остатки и выпуски лежат в одном файле — `js/config.js`.
Поправили → залили только его.

**Просмотры выпусков** обновляются одним из трёх способов — смотря где живёт сайт.
Подробно ниже, в разделе «Просмотры».

> Если после заливки изменения не видны — браузер показывает старую версию из кэша.
> Обновите страницу с `Ctrl+F5`. Для посетителей это решается настройкой
> кэширования на хостинге либо добавлением `?v=2` к подключению скриптов.

## Просмотры

Сайт берёт числа из трёх мест, от надёжного к свежему:

1. **`EPISODE_VIEWS` в `js/config.js`** — снимок, вшитый в код. Работает всегда,
   даже без сети. Это то, что увидит посетитель, если ничего не настраивать.
2. **`assets/views.json`** — файл, который обновляет скрипт по расписанию.
   Если он есть, числа берутся из него. Ключ при этом лежит на сервере
   и в браузер не попадает. **Основной способ.**
3. Запрос к YouTube прямо из браузера — только если заполнить `youtubeApiKey`
   в `js/config.js`. Тогда ключ увидит любой посетитель в исходниках страницы.
   Не рекомендую, вариант 2 делает то же самое безопаснее.

Числа из файла накладываются поверх снимка по одному ролику. Если в файле
не хватает какого-то выпуска, для него останется значение из конфига.

### Обновлять раз в час на сервере

Квота это выдержит с запасом: один запуск стоит 1 единицу из 10 000 в сутки,
то есть 24 единицы в день.

**Свой сервер / VPS (есть ssh и cron):**

```
chmod +x tools/update-views.sh
./tools/update-views.sh          # проверить руками
crontab -e
```

и строкой в crontab:

```
5 * * * * /путь/к/сайту/tools/update-views.sh >> /tmp/spotter-views.log 2>&1
```

Запуск в :05, а не ровно в :00 — в круглый час у всех пик нагрузки.

**Обычный хостинг (Timeweb, Beget, reg.ru):**
там обычно нет ssh, но есть планировщик заданий в панели и PHP. Заведите
задание раз в час с командой:

```
php /home/логин/сайт/tools/update-views.php
```

**Статика без сервера (Cloudflare Pages, Netlify):**
запускать по расписанию нечему. Варианты: настроить GitHub Actions с
расписанием, чтобы он раз в час обновлял `assets/views.json` и коммитил его,
либо просто запускать локально `powershell -File tools\update-views.ps1`
и заливать обновлённый `js/config.js` — просмотры меняются не настолько
быстро, чтобы это было заметно.

> **Проверьте после установки:** откройте `https://ваш-сайт/.env` в браузере.
> Должна быть ошибка 403 или 404. Если файл открылся и показал ключ — уберите
> `.env` выше папки сайта или закройте его правилом веб-сервера, и сразу
> перевыпустите ключ.

## Если решите завести Git

`.gitignore` уже настроен так, чтобы `.env` не попал в репозиторий.
Проверьте это перед первым коммитом: `git status` не должен показывать `.env`.
